# План: завершити рахунки постачальників, панель «Taverna Group» та тест-дані

## Що вже готове (перевірено)
Бекенд `bank-gateway` фактично повний: `get_balance`, `list_balances`, `list_movements`, `set_payout_method`, `bind_card`, `run_accruals`, `request_withdrawal`/`admin_payout`, `run_auto_withdrawals`, `charge_markup`, `list_my_shops`, `get_stats` та `group_earnings` (з розбивкою по магазинах, казначейським журналом і демо суб-рахунками MonoBank). Ролі owner/manager/staff та read-only для менеджерів реалізовані. Сторінка `SupplierBalance.tsx` і маршрути `/supplier-balance` та `/supplier-balance/:supplierId` існують.

**Головна прогалина — фронтенд не під'єднаний до готового бекенду і немає наочних тест-даних.** Саме це закриваємо.

## 1. Кнопка «Баланс» у кожного магазину (адмін-панель)
- `AdminStoreManager.tsx`: біля кожного магазину додати кнопку **«Баланс»** (іконка `Wallet`) поряд з наявними діями → `navigate('/supplier-balance/' + supplier.id)`. Admin проходить як `staff`, тож бачить повний рахунок конкретного магазину зі статистикою та розбивкою.

## 2. Нова панель «Taverna Group» (казначейство) в адмін-дашборді
- Новий компонент `src/components/admin/TavernaGroupPanel.tsx`, що викликає `group_earnings` і показує:
  - **Зведення групи:** оборот, наш заробіток (націнка), у стадіях створено / в обробці / виплачено постачальникам, к-сть замовлень, к-сть магазинів, мої магазини.
  - **Розбивка по періодам** (день/тиждень/місяць/рік) з тим самим `series`, що і в рахунку постачальника.
  - **По кожному магазину:** назва, оборот, заробіток, к-сть замовлень, статуси коштів, позначка «мій магазин»; клік → `/supplier-balance/:id`.
  - **Суб-рахунки ФОП MonoBank:** картки суб-рахунків (основний, націнка, виплати, резерв) з балансами; бейдж `sandbox`/`live`.
  - **Казначейський журнал:** останні рухи по всіх магазинах із назвою магазину, типом, сумою, провайдером.
- `AdminDashboard.tsx`: у вкладці балансів додати під-таб/секцію **«Taverna Group»** поруч із наявними «Баланси магазинів» та «Виплати за замовлення» (для admin). Модератор і далі бачить лише перегляд балансів.

## 3. Обмежений доступ менеджера — фінальна перевірка UX
- Переконатися, що для `role === "manager"` у `SupplierBalance`/`SupplierBalanceCard` приховані вивід/картка/авто-налаштування та показаний банер перегляду (логіка вже є — перевірити на реальному та тест-акаунті менеджера).

## 4. Розширені тест-дані для всіх ролей
- Розширити `seed-test-payments`, щоб наочно заповнити рахунки для тест- і реальних ролей:
  - `shop_balances` (available / pending / lifetime_paid) для кількох тест-магазинів.
  - `balance_movements` усіх типів (нарахування, націнка, вивід, списання з картки, повернення) з датами в різні періоди (день/тиждень/місяць/рік), щоб графіки були заповнені.
  - `order_splits` у трьох стадіях (створено / в обробці / виплачено).
  - `payout_methods` з демо-карткою (masked_pan) та IBAN.
  - Прив'язати частину тест-магазинів через `shop_manager_links` до профілю, щоб роль «менеджер» одразу бачила read-only рахунок.
- Кнопка «Тест-дані» вже є у `ShopBalancesPanel` (admin) — вона запускатиме розширений seed.

## 5. Під'єднання до реального банку
- Логіка вже перемикається на `live` автоматично за наявності секретів. Після плану підкажу додати `MONOBANK_TOKEN`, `LIQPAY_PUBLIC_KEY`, `LIQPAY_PRIVATE_KEY` (через безпечне сховище секретів) — до того все працює в sandbox без ризику.

## 6. Перевірка
- `curl` бекенду: `group_earnings` (admin), `get_stats`, `list_my_shops` (owner vs manager → 403 на вивід у менеджера).
- Запуск seed, далі візуальна перевірка (Playwright) рахунку постачальника, режиму менеджера, кнопки балансу в адмін-панелі та панелі Taverna Group.
- Збірка чиста.

## Технічні деталі
- Ролі магазину без нових таблиць: власник = `suppliers.telegram_id`, менеджер = `shop_manager_links.profile_id`, staff = admin/moderator.
- Заробіток платформи = `order_splits.platform_commission`; оборот = `product_total`; постачальнику = `supplier_amount`.
- Токени/IBAN не логуються; secret-ключі — лише через сховище секретів.
