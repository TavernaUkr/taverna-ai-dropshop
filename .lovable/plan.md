# План: Рахунки постачальників, доступ менеджерів та панель "Taverna Group"

## 1. Обмежений доступ для менеджерів магазину
Менеджер бачить **лише** чи надійшли кошти (баланс + статуси рухів), без виводу, прив'язки картки та авто-налаштувань.

- **`bank-gateway` (edge):**
  - У `get_balance` та `list_my_shops` додати поле `access`: `"owner"` / `"manager"` / `"staff"`. Визначення ролі: власник — збіг `telegram_id`; менеджер — запис у `shop_manager_links`; staff — admin/moderator.
  - У `request_withdrawal`, `bind_card`, `set_payout_method` заборонити виклик, якщо роль менеджера (не власник і не staff) → повертати `403 Forbidden (read-only)`.
- **`SupplierBalanceCard.tsx`:** приймає проп/визначає `readOnly`. Якщо read-only — ховати кнопки «Вивід коштів», «Прив'язати картку», перемикачі авто-виводу/авто-списання. Показувати лише баланс, суму «в обробці», «виплачено» та список рухів (надійшло/не надійшло).
- **`SupplierBalance.tsx`:** для менеджера показувати банер «Режим перегляду — керує власник», приховати керуючі елементи.

## 2. Рахунок постачальника в адмін-панелі (по кожному магазину)
- **`AdminStoreManager.tsx`:** біля кожного магазину додати кнопку **«Баланс»** (іконка Wallet) → перехід на `/supplier-balance/:supplierId`. Admin вже проходить як `staff`, тому бачить повний рахунок конкретного магазину з розбивкою та статистикою.

## 3. Нова панель «Taverna Group» (заробіток / казначейство)
Нова вкладка в `AdminDashboard` (замінює/розширює поточний таб балансів). Агрегує все:

- **Загальні показники:** сумарний оборот, наш заробіток (націнка/commission), кошти в обробці, виплачено постачальникам, кількість замовлень.
- **По кожному магазину:** назва, к-сть замовлень, оборот, наш заробіток, статуси коштів (створено / в обробці / виплачено), позначка «мій магазин» (admin-owned).
- **Витрати та перекази:** журнал рухів казначейства (виплати постачальникам, списання націнки, комісії, повернення) з фільтром.
- **MonoBank ФОП суб-рахунки:** блок під-рахунків банку (у sandbox — демо-дані: перелік суб-рахунків, баланси, останні транзакції; у live — реальні дані через MonoBank API, коли додані ключі). Кнопки перегляду та ручного переказу між суб-рахунками (sandbox-заглушки).

- **`bank-gateway` (edge):** нова дія `group_earnings` (admin-only): агрегує `order_splits` (turnover, commission=заробіток, суми за stage), кількість замовлень, розбивку по магазинах + позначку admin-owned; повертає казначейський журнал з `balance_movements`; повертає структуру суб-рахунків MonoBank (демо у sandbox).
- **Новий компонент** `src/components/admin/TavernaGroupPanel.tsx` для відображення цієї панелі.

## 4. Тест-дані балансів (для всіх ролей)
Розширити `seed-test-payments` (admin-only), щоб згенерувати наочні дані для тест- і реальних ролей:
- Баланси `shop_balances` (available/pending/lifetime_paid) для декількох тест-магазинів.
- Рухи `balance_movements` усіх типів: нарахування, націнка, вивід, списання з картки, повернення.
- `order_splits` у трьох статусах (створено / в обробці / виплачено) з датами в різні періоди (день/тиждень/місяць/рік) — щоб графіки статистики були заповнені.
- `payout_methods` з демо-карткою (masked_pan) та IBAN для тест-магазинів, щоб UI виводу/авто-налаштувань було видно у власника.
- Прив'язати частину тест-магазинів до профілю через `shop_manager_links`, щоб роль «менеджер» (тест і реальна) одразу бачила read-only рахунок.

## 5. Перевірка
- Deploy edge-функцій; `curl` тест дій `get_balance` (owner vs manager → перевірити `access` і 403 на вивід), `group_earnings`, `list_my_shops`.
- Запуск seed, потім візуальна перевірка (Playwright) рахунку постачальника, режиму менеджера, панелі Taverna Group та адмін-кнопки балансу.

## Технічні деталі
- Ролі магазину визначаються без нових таблиць: власник = `suppliers.telegram_id`, менеджер = `shop_manager_links.profile_id`.
- Заробіток платформи = `order_splits.platform_commission`; оборот = `product_total`; постачальнику = `supplier_amount`.
- MonoBank суб-рахунки: `providerMode("monobank")` вже визначає sandbox/live за наявністю `MONOBANK_TOKEN`. Live-інтеграція під'єднається автоматично після додавання ключа.
- Дотримуємось наявних патернів (session_token, service role у функції, tokens/IBAN не логуються).
